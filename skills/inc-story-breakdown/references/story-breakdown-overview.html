04 Pointing

Every Story Starts at One

Points measure human-required work, not lines of code. Writing code is cheap. What stays expensive is anything a person must decide, iterate on, or wait to verify.

1
Feature Story

The default for all feature work. A story with no flags changes existing machinery by following a pattern already in the codebase. That is most stories.

0
Recent Bug Fix

Bugs discovered within the last few weeks are fixed at no cost. Older bugs receive standard story points like any other work.

◎
The Precedent Test

Name the file or screen that already does this. Can name it, the work is derivable. Cannot name it, someone has to decide—and that is what costs.

05 Pointing

Flags Reflect What Actually Costs

Breadth is not cost—crossing many layers is nearly free. Novelty and unverifiability are cost. These stack on top of each other.

2x / 4x

Decision Density

Are we inventing machinery, or changing machinery that already runs? 2x when there is no precedent but the shape is bounded. 4x when there is no precedent and we are orchestrating an outcome in a system we do not control—external writes with partial-failure semantics, anything needing compensation or unwinding. Never fires on breadth alone.

2x / 4x

Design

Does the story create a primary view? 2x when we can name an existing screen whose layout it copies. 4x when we cannot, or when the interaction itself is novel. A whole new screen always scores at least 2x.

2x

Verification

Can a passing test prove this works? Fires on correctness that depends on production-shaped data, background jobs on a cron cadence, eventual consistency, migrations and backfills.

2x

Communication

Requires coordination with domain experts, stakeholder sign-off, cross-team handoffs, or third-party providers (Coinbase, Alchemy, etc.). Waiting on a human is still waiting on a human.

points = 1 × decision density × design × verification × communication

Story 2 bundles schema, API and screen deliberately—we never split a layer from its only consumer. Story 4 cites no precedent, which is exactly why it costs.

07 Design

When Stories Need Design

Frontend is the most human-required work in a build, so this flag matters more than any other. We count only primary states—what the feature exists to show and do. Empty, loading, submitting, validation and error states are templated and never counted.

Before: One blocked story

"Build the multi-step onboarding wizard"

8 pts — but blocked until design is finalized, so dev can't start.

→
Design Story

Design decisions, mockups, and review. Blocked on human designer.

Implementation Story

Build the designed UI. Starts as soon as design is approved.

We split into design and implementation stories only at 4x—where there is no precedent screen to copy, or the interaction itself is novel. At 2x the design is decidable while building, and splitting only adds ceremony.

09 Reference

Point Scale at a Glance

Points What It Means
1 No flags. Changing existing machinery by following a named precedent. Most stories land here.
2 One flag at 2x. A new primary view in an established design system, or work a test cannot prove.
4 Two flags, or one flag at 4x. Genuinely novel UI, or orchestration in a system we do not control.
8 Two kinds of hard at once. Usually worth splitting—they often need different attention.
16 Split this. Almost nothing should reach here intact.

Higher points don't mean "harder"—they mean more human judgment is at play. A 2-point story can still be the riskiest thing in a build, which is why we attach a written risk note rather than inflating the number.
